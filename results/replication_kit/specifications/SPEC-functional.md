# FCCSMS Functional Requirements (test-authoring source)

**Version 1.0 — frozen 2026-08-12, before any test was written.**

This is the sole functional source for test authoring in **both** arms. It was
written from the application's configuration constants, controller flow and
database schema. It does not reference the seeded-defect register, and no
requirement below was worded to describe a seeded defect.

Requirement IDs are cited by every test in both arms. A test that cites no
requirement is out of protocol.

---

## MOD-01 Case intake and registration

- **FR-01.1** Registration requires first name, last name, a valid email address, and a password of at least 8 characters, confirmed.
- **FR-01.2** Date of birth is required, must not be in the future, and the applicant must be at least 18.
- **FR-01.3** A phone number is required and must be a North American format: optional parentheses around a 3-digit area code, optional separator, 3 digits, optional separator, 4 digits.
- **FR-01.4** Street, city, a 2-letter state code, and a 5-digit (optionally ZIP+4) postal code are required.
- **FR-01.5** SSN last-4 is required and must be exactly 4 digits.
- **FR-01.6** Household size must be an integer between 1 and 20 inclusive.
- **FR-01.7** The justification narrative must be at least 50 characters after trimming.
- **FR-01.8** Every form control has a programmatically associated accessible name.

## MOD-02 Eligibility engine

- **FR-02.1** Evaluation returns one of `passed`, `flagged`, `failed`, plus a per-rule breakdown.
- **FR-02.2** Any failed hard-stop rule makes the overall result `failed`, and the first such reason is reported as the stop reason.
- **FR-02.3** If no hard stop fails but any flag rule fires, the result is `flagged`.
- **FR-02.4** Age hard stop: an applicant under 18 fails.
- **FR-02.5** Active-benefit hard stop: an existing Approved application for the same programme fails.
- **FR-02.6** Application-limit hard stop: 3 or more other active applications fails. Active statuses are those listed in `ACTIVE_STATUSES`.
- **FR-02.7** Poverty flag: annual income above 1.85 times the household poverty threshold is flagged for officer verification.
- **FR-02.8** Poverty thresholds follow `POVERTY_THRESHOLDS` for households of 1–8, plus `POVERTY_ADDITIONAL_PER_PERSON` for each additional member.
- **FR-02.9** Income-inconsistency flag: annualised monthly expenses above 150% of annual income is flagged.

## MOD-03 Role-based access control

- **FR-03.1** `requireRole` admits a session only when its role identifier is a member of the permitted set.
- **FR-03.2** Role identity is an integer. A value of a different type that merely compares equal is not the same role.
- **FR-03.3** A JWT is accepted only when its HMAC-SHA256 signature matches the payload under the server secret.
- **FR-03.4** A JWT is rejected once past its `exp` claim.
- **FR-03.5** `GET /applications` returns, for a citizen principal, only applications belonging to that citizen.

## MOD-04 Case and appeals workflow

- **FR-04.1** A case status change is permitted only where the target appears in `VALID_TRANSITIONS` for the current status.
- **FR-04.2** `Approved` is reachable only from `Supervisor Review`.
- **FR-04.3** A supervisor decision requires a non-empty justification comment.

## MOD-05 SLA tracking

- **FR-05.1** SLA deadlines advance in business days; Saturday and Sunday do not count.
- **FR-05.2** Adding *n* business days to a Friday lands on the following week, never on the weekend.
- **FR-05.3** A tracking row whose deadline has passed and which is not yet marked breached is marked breached when breaches are checked.
- **FR-05.4** A tracking row whose deadline has not passed is not marked breached.

## MOD-06 Document and attachment handling

- **FR-06.1** Upload admission is decided by the content-sniffed MIME type, matched against `ALLOWED_MIME_TYPES`.
- **FR-06.2** A file above `MAX_FILE_SIZE` (5 MB) is rejected.
- **FR-06.3** No more than `MAX_FILES` (10) documents may attach to one application.
- **FR-06.4** A file reported with an upload error is rejected.
- **FR-06.5** The name a file is stored under on disk is generated by the system.

## MOD-07 Notifications

- **FR-07.1** A notification is addressed to exactly one recipient.
- **FR-07.2** A notification may be marked read only by its recipient.
- **FR-07.3** Notification bodies are rendered into HTML pages.

## MOD-08 Reporting, search and audit trail

- **FR-08.1** The audit log may be sorted by a caller-supplied key.
- **FR-08.2** A sort key that is unrecognised falls back to the default ordering (most recent first).
- **FR-08.3** Audit records are append-only: the system retains them for the applicable retention period and provides no supported deletion path.

## MOD-09 Authentication and session

- **FR-09.1** A state-changing request carries a CSRF token that must match the one held in the session.
- **FR-09.2** Authentication establishes a fresh session identifier.
- **FR-09.3** A failed login is recorded in the audit trail.
- **FR-09.4** After `MAX_FAILED_LOGINS` (5) consecutive failures the account is locked.
- **FR-09.5** A session idle beyond `SESSION_TIMEOUT` (1800s) is no longer authenticated.

## MOD-10 Risk scoring

- **FR-10.1** Score bands are: low below 25, medium 25–49, high 50–74, critical 75 and above.
- **FR-10.2** Cases graded high or critical require Quality Review before Supervisor Review.
- **FR-10.3** The risk score is recomputed when the evidence set for an application changes.

## MOD-11 AI case-summary assistant

- **FR-11.1** The assistant returns a summary, a recommendation, and the set of tool calls it made.
- **FR-11.2** The recommendation is one of `approve`, `deny`, `refer to officer review`.
- **FR-11.3** Where no basis for a disposition is present, the recommendation is `refer to officer review`.
- **FR-11.4** The assistant is advisory: it never writes a case status.
- **FR-11.5** The assistant may call registry tools on behalf of the officer it is acting for.
- **FR-11.6** The summary is rendered into an HTML page.
